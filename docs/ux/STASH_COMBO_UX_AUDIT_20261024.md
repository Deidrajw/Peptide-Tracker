# Stash, Add Kit and Log Combo Dose — visual/interaction audit

Status: **PROPOSED — USER APPROVAL REQUIRED, NO APPLICATION CODE CHANGED**  
Audit date: 2026-10-24  
Verified GitHub main baseline: `2da1001a43812819266066159cb7f2d73746e3c1` (v0.9.7-beta)  
Evidence: user-supplied physical-iPhone screenshots, current `assets/js/05-nexus.js`, `07-nexus.js`, `10-nexus.js`, and continuity documents.

## Findings and source behavior
1. **Log Combo Dose scales poorly.** `comboDoseModal()` builds one full-width toggle per eligible tracked compound, all present simultaneously. 50 compounds means 50 tall rows before dose amounts/date/time/symptoms/save. Current Favorites is a wrap of chips, with a delete glyph inside a preset selection button (separation of select/delete affordances needed). Prepared mixed syringes are distinguished from presets and must remain so; existing per-compound dose/source/schedule/history semantics must remain untouched.
2. **Add Kit uses a native long select.** `supplyModal()` combines built-in, nonblend library and custom compound names in `#sname` without filtering. `NUMBER OF VIALS` and `MG PER VIAL` use tight two-column input groups. It has existing conditional 'I already have a vial open', recon date/remaining, metadata-only edit protections, blend routing and no data migration — preserve all.
3. **Stored card presentation depends on top-level `vialMg`.** In `assets/js/10-nexus.js`, `headlineMg = currentReconDate ? vialRem : (s.vialMg>0 ? totalMg : null)`; its conditional also controls rendering the progress bar. A conventional unopened one-vial kit renders a full 100% bar, while a stored blend without usable top-level vialMg renders `No vial reconstituted yet`. The screenshot's Deadpool saved record cannot be inspected privately; do not claim its persisted field schema or mass is defective before isolated fixture testing. This is **not** a one-vial threshold. Do not manufacture a percent for a blend or sum inconsistent units.
4. **Stash Details disclosure is over-dense.** Large nested lists of opened vials and dose history run very long, with separate show-breakdown toggles and repeated 3-column microtype for quantity, vial states, concentration; buttons Edit/Reconstitute/Intel/Manage compete visually. Legacy Unicode disclosure symbols and mixed chevrons are inconsistent, especially next to native <details> markers. Full history must remain reachable, but should not load as unbounded visual content.
5. Screenshot shows crowded iOS top/status-bar area in several situations. Need validate Safari vs standalone PWA, safe-area and scrolling conditions in real iPhone before changing CSS; cannot infer precise device cause from screenshot alone.

## Proposed UX — preview first
- **Log Combo Dose:** one compact section `Selected (N)` with removable compact selected chips and a search-first multi-select combobox. Show short suggestions + recent/favorites by default, filtered full list when typing, internal maximum list height; optionally show a browse-all sheet. Do NOT switch semantics abruptly at 10; search should work for any library size, and an adaptive 10+ compact mode is optional if it genuinely improves discoverability. Two-stage flow: select compounds, then show dose amount per selected compound and shared date/site/notes/symptoms with sticky Review & Log action. Preserve draft and scroll when picking. Explicit summary of per-compound allocations and conflicts before committing. Distinguish saved favorites from already-prepared syringes. Delete favorite via explicit secondary action with confirmation, never nested button.
- **Add Kit:** searchable single-select compound combobox (including custom names), separate `Standard compound` and `Blend` entry choice, hierarchical groups Inventory (compound, vial count, size), Optional already-open vial, Preparation (diluent and expiry), More details (cost/currency/storage/notes). Protect metadata-only edit and vial-count/vial-size immutability. Show correct unit labels for compound versus blend; do not show an unvalidated recipe.
- **Stash cards:** for stored/sealed kit, show name + status + one-line `1 sealed vial · 15 mg per vial` (for qualified standard kits) or `1 sealed blend vial · Components: 3` (when known) without a fake 100% usage bar. For active kit show remaining quantity plus a meaningful fill progress and expiry, with one principal next action. Expiring gets separate date alert, never imply sealed vials expire due to post-reconstitution timer. Details opens organized `Inventory`, `Vial history`, `Dose history` with searchable/paginated history beyond a reasonable count; three-line expanded 'all 24 doses' not default. Preserve vial-to-dose source breakdown, exact totals and reversals. Prioritize primary Open/Prepare and move infrequent Edit/Intel/Manage into separate contextual menu using already approved bottom-sheet interaction pattern.
- **Consistency:** standardized outline icons/chevrons, 44–48px tap targets, compact section spacing, contrast, theme support, keyboard inset/safe area, no double-scroll. At 320/390 widths test both themes with 5, 10, 50 compounds; 0, 1, 10, 100 history rows; 0/1/many vials; active/sealed/finished/expired/blend; missing/invalid values and two kits for same compound.
