## Findings requiring code and regression correction (not safe to release)
1. **Prepared dose/syringe Undo still has unlocked in-memory-only paths** — assets/js/05-nexus.js lines ~2646, ~2689, ~2752: toast callbacks remove `state.preparedDoses`, credit stock with `undoConsumeCompoundInventory` and call `render()` without `await nexusCommitCurrentState()`, event-specific exclusive writer or stale/readback checks. They are reachable from `prepareDosesModal` for blend/multi-count/single syringe. Risk: UI shows undo but durable state remains unchanged; later save may persist stale inventory mutations. This falls outside existing static gateway checks and warrants reopening the broader **P0 legacy safety gate**. Do not remove old data models blindly; migrate callback to exact recorded allocation/event transactional reversal with negative/insufficient/stale/double-undo regression.
2. **Older Reconstitute Vial modal still callable** — assets/js/05-nexus.js ~2763+ still builds original inline RECONSTITUTE header and 18px text ✕, and calls `activateVial()` through a separate layout, rather than new form-first `openNewVialModal`. Active entry points in assets/js/12-nexus.js ~946 (.inv-notice-action openvial), ~1029 (.reconkit), assets/js/05-nexus.js ~231, ~1533, ~2570. Risk: inconsistent form-first nasal/injectable selection, shared X geometry, and separate activation behaviour. Must distinguish valid preexisting reconstitution editing from creating/opening new vial; redirect only equivalent paths after validating continuation/draft preservation.
3. **Finish Vial modal retains legacy UI and mutation-first model** — assets/js/09-nexus.js ~1111–1191 uses inline old-style header and text ✕; reached via manageKitMenu in assets/js/04-nexus.js ~1479/~1556, and .finishvial in assets/js/12-nexus.js ~960. `finishVial()` alters remainingMg/status before entering Log Dose; `finished:true` bypasses later deduction. Even though final commit awaits `nexusCommitCurrentState`, a vial can be finished before a dose is actually confirmed. Product promise/ledger history risk and duplicate design language; requires isolated scenario tests before consolidation.
4. **Compound-level Use setup duplicates per-vial/product form paths** — assets/js/05-nexus.js ~701–765 `nexusUseSetupModal` still shows old ✕, legacy top-level ADMINISTRATION dropdown and method/source/tracking preference; exposed from Stash card in assets/js/10-nexus.js ~301/~2320 and Log Dose ~1284. Separate `nexusStashSetLegacyVialMethod` exists in assets/js/10-nexus.js ~2347 and per-vial form-first Open New Vial in assets/js/09-nexus.js ~1782. These are different concepts, not necessarily duplicate data, but overlapping user-facing prompts; audit persisted `nexusUseSetups`, exact source and per-vial labels before unifying/removing.
5. **Release test gap:** tools/validate-storage-writers.mjs scans unlocked direct main-store writes and `saveState` calls, but does **not** reject callbacks that mutate stock/history and render without any persistence. Add static/actual browser regression for all legacy prepared-syringe Undo variants, multi-kit allocations, double-undo, stale tab, write failure, reload readback.
