## Audit method / critical distinction
- `CODED` means documented draft implementation, not necessarily visually approved. `AUTOMATED` means tests were reported passing on a specified commit; tests often cover only a narrower path. `DEVICE OPEN` means user has not supplied passing physical Safari/keyboard/VoiceOver evidence for the *current implementation*. `DISCOVERY` means an idea or proposed design, not approved code.
- A prior-head CI green result does not close a subsequent device report or prove an untested component. Keep user-reported failures until directly resolved.
- Both DS2 sprint documents still include historically accurate but outdated labels like `PLAN / NOT IMPLEMENTED`; later draft code exists. Treat their original scope as requirements, not their old status label as today's state.
- The four continuity files total approximately 784,000 characters, with hundreds of append-only headings, repeated historical `ONE NEXT ACTION` notes, and no single current requirement-to-evidence ledger. The latest appendix is not proof every older requirement was closed.
- This document is the current **open-item index**; the continuity files retain their chronological evidence. Reverify branch/CI before implementation.

## B. Documentation and status-control defects
1. **No single current DS2 register**: Sprint 01/02 documents are historical proposals; PROJECT_STATE (hundreds of append sections) mixes active instructions with obsolete next actions. This audit provides a working crosswalk without deleting historical evidence.
2. **No closure criteria per screen**: A source commit, CI test, cloud preview and user acceptance are different. Require each DS2 row to carry status: proposed / coded / automated tested / physical iPhone accepted / deployed, separately.
3. **Misleading statuses after later commits**: RELEASE_HISTORY ends with a pending reaction milestone even though REGRESSION/PROJECT_STATE document subsequent passing CI. Append reconciled milestone; do not rewrite chronology.
4. **Conditional Sprint 01 closure**: Calendar Month icons were explicitly left unresolved. Sprint 02A/02B were extensively coded despite Sprint 01 signoff not fully documented.
5. **Cloudflare primary vs GitHub Pages**: Historical PROJECT_STATE header still says GitHub Pages as production while newer development uses Cloudflare. Record verified origin and source SHA per deployment, do not treat bot preview as live production.
6. **Commit/manifest ambiguity**: GitHub Actions PR validation may use synthetic merge SHAs; branch HEAD, tested checkout, artifact source commit and published Cloudflare commit must be tracked distinctly.
7. **Protected safety and data flows**: 80/80 calculator diagnostics and vial regression are not clinical safety validation. Legacy uploads/user records and dose math are not to be tested against real storage without user consent.
